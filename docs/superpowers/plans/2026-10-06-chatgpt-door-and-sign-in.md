# ChatGPT door and sign-in — implementation plan (slice 1 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ChatGPT connects to its own address, `/api/chatgpt/mcp`, on the same server, can sign a listener in with Clerk, and can save a song — while `/api/mcp` stays byte-for-byte what Alexa+ gets today.

**Architecture:** `buildMcpHandler` gains one option, `surface: "voice" | "chat"` (default `"voice"`). The chat surface hides the three membership tools, declares `securitySchemes` on every tool, and answers a signed-out call to a signed-in tool with a tool error carrying `_meta["mcp/www_authenticate"]` instead of the HTTP 401 gate. A new route serves the chat surface and accepts tokens issued to a second, ChatGPT-only Clerk OAuth client.

**Tech Stack:** Next.js route handlers, `mcp-handler` (`createMcpHandler`, `withMcpAuth`), `@modelcontextprotocol/ext-apps` (`registerAppTool`), vitest, Clerk OAuth (dev instance `creative-dory-9232`).

**Spec:** `docs/superpowers/specs/2026-10-06-chatgpt-app-design.md` (sections "Architecture", "Sign in, save, follow", "Kept off the ChatGPT door", "What stays exactly the same for Alexa+").

## Global Constraints

- `/api/mcp`'s tool list, tool descriptions, replies, card page, sign-in gate and timings do not change. Task 1's snapshot must pass unmodified after every later task.
- Nothing merges to `main` before the Alexa+ submission (October 23). Work stays on `feat/chatgpt-app`.
- `npm test`, `npm run typecheck`, `npm run build` green before any PR.
- No production deploy from this branch. Hand tests use a Vercel preview deployment.
- No new dependencies. Do not install `@openai/mcp-extensions`.
- Sign-in scopes are exactly `openid`, `profile`, `offline_access`.
- Secrets only in env: `CLERK_CHATGPT_OAUTH_CLIENT_ID` (new). Never log a token or listener id.

## Review Focus

1. **An Alexa+ token sent to the chat door** must be treated as signed out (it was issued to a different client), and **a ChatGPT token sent to the Alexa door** likewise. Tests: Task 4.
2. **A junk or expired bearer on the chat door** must still reach the tool and get the sign-in error (HTTP 200, `isError`), never an HTTP 401 that ChatGPT can't act on. Test: Task 5.
3. **A signed-in ChatGPT listener** must still not see `support_radio_milwaukee`, `my_membership` or `cancel_membership` in the tool list. Test: Task 2.
4. **Card tools on the chat door** must keep `_meta.ui.resourceUri` after `securitySchemes` is merged into `_meta`, or every card disappears. Test: Task 3.
5. **The Alexa door's tools/list** must not gain `securitySchemes` (the patch is chat-only). Test: Task 1 snapshot.

type ClientIdVar = "CLERK_LISTENER_OAUTH_CLIENT_ID" | "CLERK_CHATGPT_OAUTH_CLIENT_ID";

function tokenVerifier(clientIdVar: ClientIdVar) {
  return async (_req: Request, bearer?: string): Promise<ListenerAuthInfo | undefined> => {
    const { CLERK_LISTENER_ISSUER: issuer, CLERK_LISTENER_JWT_KEY: pem } = process.env;
    const clientId = process.env[clientIdVar];
    if (!bearer || !issuer || !pem || !clientId) return undefined;
    try {
      const claims = verifiedClaims(bearer, publicKeyFrom(pem));
      if (!claims || claims.iss !== issuer || typeof claims.sub !== "string" || !claims.sub) return undefined;
      if (typeof claims.exp !== "number" || claims.exp <= Date.now() / 1000) return undefined;
      if ((claims.client_id ?? claims.azp) !== clientId) return undefined;
      const scopes = typeof claims.scope === "string" ? claims.scope.split(" ").filter(Boolean) : [];
      return { token: bearer, clientId, scopes, expiresAt: claims.exp, extra: { userId: claims.sub } };
    } catch {
      return undefined; // malformed token or key; never log the token
    }
  };
}

/** Alexa+ door: tokens issued to the Alexa+ account-linking client. */
export const verifyListenerToken = tokenVerifier("CLERK_LISTENER_OAUTH_CLIENT_ID");
/** ChatGPT door: tokens issued to the ChatGPT client (same Clerk app and listeners, a second OAuth client). */
export const verifyChatGptToken = tokenVerifier("CLERK_CHATGPT_OAUTH_CLIENT_ID");
```

import { generateProtectedResourceMetadata, getPublicOrigin, metadataCorsOptionsRequestHandler } from "mcp-handler";
import { OAUTH_SCOPES } from "@/lib/listenerAuth";
import { CHAT_RESOURCE_PATH } from "@/lib/mcp";

// RFC 9728 path form: the metadata for /api/chatgpt/mcp lives at /.well-known/oauth-protected-resource/api/chatgpt/mcp.
function handler(req: Request): Response {
  const metadata = generateProtectedResourceMetadata({
    authServerUrls: process.env.CLERK_LISTENER_ISSUER ? [process.env.CLERK_LISTENER_ISSUER] : [],
    resourceUrl: `${getPublicOrigin(req)}${CHAT_RESOURCE_PATH}`,
    additionalMetadata: { scopes_supported: [...OAUTH_SCOPES] },
  });
  return Response.json(metadata, { headers: { "Access-Control-Allow-Origin": "*", "Cache-Control": "max-age=3600" } });
}
const options = metadataCorsOptionsRequestHandler();

export { handler as GET, options as OPTIONS };
```
